# Codex Monitor

一个用于查看 Codex 订阅额度的 macOS 菜单栏小应用。启动时读取一次；展开面板时，距上次成功查询超过 1 分钟便自动更新，也可随时点击“刷新”。没有后台轮询或实时监测。

## 使用前准备

当前已验证的环境是 Apple Silicon Mac、macOS 27.0.1、Xcode 27.1、Swift 6.4。工程要求 macOS 27.0 或更高；其他系统版本、Intel Mac 尚未验证。

- 已安装 Xcode，能在终端运行 `swift --version`。Xcode 提供编译工具，Swift 是本项目使用的编程语言。
- 本机已有可用的 Codex，且已通过订阅账号登录。应用复用已有登录，不提供登录页面，不支持 API Key 登录。
- 查询时能够连接 Codex 服务。

当前程序使用的 Codex 路径为：

```text
/Users/shihanxi/.vscode-insiders/extensions/openai.chatgpt-26.1007.21434-darwin-arm64/bin/macos-aarch64/codex
```

这是当前 Mac 的 VS Code Insiders 扩展附带的程序，扩展升级或换电脑后路径可能变化。路径不同时，先按下方“修改 Codex 路径”调整，再构建。

## 第一次构建和启动

打开 macOS 的“终端”，依次运行以下命令。第一行进入当前项目目录；如果你移动了项目，请替换这个目录。

```sh
cd /Users/shihanxi/AI/project/monitor
./scripts/build-app.sh
open build/CodexMonitor.app
```

第二行把 Swift 源码编译成应用，并输出 `Application: .../build/CodexMonitor.app`。首次构建需要一些时间；出现错误时先处理错误，再启动应用。

启动后，屏幕顶部菜单栏会出现仪表盘图标，鼠标悬停显示“Codex Monitor”。它没有 Dock 图标，也不会弹出独立桌面窗口。点击仪表盘打开面板，等待首次查询完成。

以后无需重新构建：在 Finder 中进入项目的 `build` 文件夹，双击 `CodexMonitor.app` 即可。也可以在项目目录再次运行 `open build/CodexMonitor.app`。

## 查看额度、刷新和退出

- `5h` 与 `Weekly` 分别表示服务返回的五小时和每周额度窗口；其他周期按服务提供的名称展示。
- “剩余”比例和进度条表示当前剩余额度；“重置时间”使用本地日期和时间；“查询时间”表示上次成功读取的时刻。
- 数据缺失时显示“暂无数据”，不会把未知额度当成 0% 或 100%。
- 额度标题下方的“重置卡”显示剩余张数、服务提供的卡片有效期，每张卡占一行，不展示营销标题或说明；内容较多时可在面板中滚动。只有数量而没有明细时会明确提示，不根据明细条数推算剩余卡数；本面板不兑换或消耗卡片。
- 点击“刷新”重新查询。读取时显示“正在读取额度…”，刷新按钮禁用；结束后显示新数据或错误提示。展开触发的自动刷新会保留旧额度和查询时间，并显示“正在更新…”；失败时清除旧数据并显示错误。
- 再次点击仪表盘，或点击桌面、其他应用或菜单栏组件，可收起面板；重新展开时，距上次成功查询超过 1 分钟才自动刷新；一分钟内复用数据。读取中或限流等待期不重复请求，收起后不会定时查询。
- 点击面板中的“退出”关闭应用。读取中也可以退出，程序会取消本次读取、完成专用进程清理，然后移除图标。

应用只允许一个实例。重复启动不会增加图标；更新版本前，请先从旧面板点击“退出”，再重新构建和启动。

## 修改 Codex 路径

用编辑器打开 [CodexMonitorApp.swift](Sources/CodexMonitor/CodexMonitorApp.swift)，找到 `CodexReader(executable: URL(fileURLWithPath:` 下一行的完整路径，只替换双引号中的内容。使用已确认可运行的 Codex 可执行文件的绝对路径，例如以 `/Users/` 开头的路径；不要填写扩展文件夹或仅填写 `codex`。

保存文件后，在项目目录重新运行：

```sh
./scripts/build-app.sh
open build/CodexMonitor.app
```

直接从 Finder 启动不依赖终端的 PATH。应用不会把 Codex 或账号凭据复制进应用包。

## 常见问题

| 现象 | 处理方式 |
|---|---|
| 构建时找不到 Swift 或开发工具 | 确认 Xcode 已安装并完成首次启动配置；使用 `xcode-select -p` 检查开发工具目录 |
| 启动后没有独立窗口 | 点击屏幕顶部仪表盘图标；本项目是菜单栏应用 |
| 启动新版却仍显示旧内容 | 先退出已运行的旧实例，再启动 `build/CodexMonitor.app`；旧 `.build/Preview` 是历史预览包 |
| “未找到 Codex” | 检查上述绝对路径是否仍存在，扩展升级后调整路径并重新构建 |
| 提示完成订阅登录 | 先在已有 Codex 中完成有效订阅登录，再回本面板手动刷新 |
| 请求失败或超时 | 检查网络，稍后手动刷新；程序不会自动重试 |
| 查询受到限流 | 等待后再刷新；若显示可重试时间，在该时间前刷新按钮保持禁用 |
| 返回格式不兼容 | 核对本机 Codex 版本；当前验证版本为 `0.162.0-alpha.17.2`，其他版本尚未验证 |
| 未能确认读取进程退出 | 按提示退出应用，检查后再重试；不要以同名进程为依据终止其他 Codex 应用 |

## 验证结果和限制

2026-10-18 首版验收：全套 42 项测试通过，含真实订阅查询，无跳过、无失败。用户已确认正式应用包的真实额度显示、连续三次刷新、展开收起和读取中退出正常；退出后应用进程已结束。

认证失效、服务错误、限流、缺失字段、超时和异常进程退出主要使用本地替身或构造数据验证。没有主动断网、注销真实账号或触发真实限流；这些真实故障场景未验证。原菜单栏自动测试的隐藏初始状态问题已修复。逐项证据与历史问题见 [开发与验收记录](docs/development-log.md#task52-首版验收回放)。

当前没有后台定时刷新、登录设置页、开机启动、历史记录、持久化缓存或桌面固定窗口。每次查询有 20 秒总截止时间，之后的有界清理可能额外花费少量时间。限流只解析已支持的明确错误及秒数形式的 Retry-After，暂不支持 HTTP 日期形式。

打包脚本生成本机 Release 应用，使用 ad-hoc 签名，不需要开发者证书；尚未提供公证或其他 Mac 的分发包。源码和脚本由 Git 管理，`build/`、`.build/` 中的构建产物被忽略。当前只在上述环境验证。
